# Provider credential review

Providers save their license/insurance claims on their profile, then upload a license or insurance certificate under **Credential documents**. Accepted files are PDF, JPEG, PNG and WebP, up to **4MiB** each. Images are decoded and re-encoded with metadata removed; PDFs are delivered as downloads, never embedded. Do not upload W-9 forms, Social Security numbers or tax identification numbers. The optional W-9 status note is not collected by this change.

The upload uses a **separate private Vercel Blob store** through `PROVIDER_DOCUMENT_BLOB_READ_WRITE_TOKEN`. That token must differ from the existing public-media credential. No resource is provisioned automatically and no public-store/OIDC fallback is used. Missing configuration returns 503 before writing a blob. Existing amenity/avatar media behavior is unchanged. The application limit plus bounded multipart overhead stays below Vercel's server-upload request limit.

Files are stored under a server-generated pathname with `access: 'private'`. Storage URLs, paths and credentials are never returned to browsers. The provider owner and an active Bundleen administrator may download the current document through `/api/provider/credentials/{id}`. Ordinary operations staff, HOA managers, residents and unrelated providers cannot read these files. Operations staff retain their existing provider support-detail and account-status workflows, with the new private credential DTO redacted and credential-review actions denied. Every download rechecks live authorization and current-document ownership, streams the private object with `private, no-store`, attachment disposition, sandbox CSP and `nosniff`; there are no public or signed download links.

Uploading a replacement invalidates the matching verification immediately. Its immutable bytes/checksum and the credential-claim snapshot are tied to the provider's current document pointer. The old file becomes inaccessible; deletion of superseded private bytes is best-effort, with a sanitized operational warning if cleanup fails. Failed database attachment rolls back and attempts to delete the newly uploaded private object. Retained database metadata records the evidence version without a public location.

An administrator reviews the submitted claims beside the current document, records a confirmed expiry date and, for insurance, the coverage amount and additional-insured status. Approval requires the exact document ID/checksum and reviewed profile version. Rejection requires a reason. Profile changes, document replacements, approval/rejection/revocation and their audits share the same optimistic concurrency guard; a stale review cannot approve replacement evidence. Legacy timestamps without current document proof do not create a badge.

Expiry dates are **valid through the stated UTC calendar date**. For example, a document expiring on January 31 remains current through January 31 UTC and is expired at February 1 00:00 UTC. Profile and bid badges and new-award eligibility evaluate expiry and exact current proof at read/write time; they never wait for the daily worker.

The HOA manager or an authorized Bundleen administrator can configure the minimum insurance coverage and additional-insured requirement in the community workspace. Policy edits are audited and reassert manager/admin authority inside the transaction. Both credentials must be current for a new award, and an HOA award must meet its current insurance policy. A database acceptance guard locks and checks the current provider/evidence/policy as part of the award transaction, including concurrent replacement or revocation. Existing awarded visits remain completable when credentials later expire; suspension protections remain in force.

The existing authenticated daily `/api/jobs/outbox` job processes a bounded batch of expired documents and 30/7-day renewal reminders. Notification/outbox dedupe keys and per-document reminder claims are committed together. A new approval resets the reminder markers. A late run catches the relevant remaining window rather than sending an obsolete 30-day message after the seven-day window has begun. Each run clears both expired credentials for a provider when both are due, reloading the shared profile version between them. Larger backlogs drain across scheduled invocations; operators can invoke the authenticated worker again without duplicate delivery. The worker must be configured by an authorized operator; code does not imply that credentials or a schedule were provisioned here.

## Release prerequisites and evidence

Verify migrations and integration suites on an approved disposable database first; those suites can truncate data and must never target a shared application database. `npm run build` deploys migrations, so use it against a shared database only for an explicitly authorized deployment. Build-only verification uses `npx next build` with a synthetic/local environment. Never copy real credentials into tests or commit secrets.

The testing database's catalog comparison identified five missing historical community guards. `20261110000000_restore_community_baseline_guards` restores only their effective main definitions, in one transaction with bounded locks. It rejects invalid existing active staff assignments, and its unique index rejects duplicate active HOA managers; resolve any reported data conflict separately before retrying. It does not change historical checksums, replay provider backfills or rewrite application data. Run `scripts/provider-credential-preflight.sql` with a PostgreSQL client against the authorized target before applying it; all four conflict counts must be zero. Compare the catalog again afterward.

Storage provisioning, environment connection, migrations and deployment are separate authorized operator steps. Preview builds skip migrations, so their database must already have the approved schema. The separate private store credential is required for a real upload/download smoke test; mocks cannot prove storage isolation. Coordinate the schema and new application/worker cutover: legacy verification timestamps alone no longer permit new awards, and existing providers need current approved documents. Existing awarded visits remain completable with the new application.

The authenticated `/api/jobs/outbox` endpoint is a mutating worker, not a readiness check: it advances due marketplace windows, queues service and credential reminders, clears expired verification and delivers pending mail across its database. Ordinary application mutations can also schedule an `after()` outbox drain. Disabling Preview cron alone therefore does not prevent mail delivery. Prefer isolated smoke fixtures, synthetic recipients and a private test store; if shared testing is explicitly approved, confirm queued recipients/mail transport and coordinate both existing application and worker activity before mutating checks.
