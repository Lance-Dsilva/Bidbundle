# N04 external native navigation protocol

Use only fresh task-owned runtimes after the exact source checkpoint. Same synthetic fixture guards and driver as N02; no shipping fixture branch, exported input hook or real service calls. Target integration_test/native_navigation_test.dart using `flutter drive --flavor development --debug --driver=test_driver/native_journeys_driver.dart --target=integration_test/native_navigation_test.dart -d DEVICE_ID`. Evidence directory uses BUNDLEEN_FIXTURE_EVIDENCE as before.

Two homeowner scenarios, 100% / 200%. Flutter tester taps set up Requests/detail and Account/Inbox/conversation; these taps are not OS-input evidence. At each `N04_READY homeowner SCALE STEP ACTION` line the reviewer must verify the displayed route and deliver the named input on that exact device. Route transitions wait at most 90 seconds and print N04_OBSERVED only after the production model changes. No tester BackButton tap, handlePopRoute or drag substitutes for external inputs in these checkpoints.

Android: installed adb supports `adb -s EXACT_SERIAL shell input keyevent KEYCODE_BACK`. Record command/result and route before/after for request-detail-back, inbox-detail-back, inbox-list-back and account-top-back. For signed-out-back, the app may normally background/exit; do not force an in-app route transition. Harness observes model state for 30 seconds, but a pass alone does not prove external delivery. Record delivery and foreground/activity outcome independently; if activity exit interrupts test, report that result and existing cleared-state evidence rather than calling interruption an app bug. Reviewer may need to bring the same synthetic test activity forward before the next scenario without changing app/session state.

iOS: installed simctl io/ui help provides screenshots/video/settings but no generic swipe injection. Existing RunnerTests is a unit-test target, not an XCTest UI runner. Only run gesture claims if the reviewer confirms and uses a documented native Simulator UI drag/gesture API through available computer-use tooling. No guessed simctl/private API. For the three nested-route checkpoints use a real left-edge-to-right swipe; root Home tab selection is explicitly tester setup, since a top-level tab has no iOS pop route. Signed-out swipe has no route to restore and must retain cleared state. If native input is unavailable, mark iOS OS-gesture evidence open; do not report tester gestures as equivalent.

Capture device ID, OS, scale, exact source SHA, delivered input and observed route/state. Optional OS screenshots/video complement synthetic driver screenshots. Existing semantic label checks and effective text scale are retained; this suite does not establish spoken screen-reader output, focus traversal/order under TalkBack/VoiceOver, switch control, physical device gestures or hardware-key reliability. No host/user accessibility settings are changed. Any production change requires a reproduced defect and manager review.
